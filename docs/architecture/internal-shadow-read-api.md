# Internal Shadow Read API

## Objective

This document defines the internal v1 read-only API for LangGraph shadow
evidence and neutral shadow run visualization. It is intended for controlled
internal TEST access and future admin UI consumption.

It does not create a public API, does not implement UI, does not benchmark n8n,
does not execute SQL, and does not call Gemini, Watson, n8n, LangSmith, Studio,
or tracing services.

## Endpoints

```text
GET /v1/internal/shadow-runs/{shadow_record_id}
GET /v1/internal/agent-runs/{agent_run_id}/shadow-runs?limit=50
GET /v1/internal/shadow-runs/{shadow_record_id}/visualization
```

No write, update, delete, replay, execute, repair, finalize, or create endpoint
is exposed by this API.

## Safe Projection

`GET /v1/internal/shadow-runs/{shadow_record_id}` returns a deliberate safe
projection. It never returns `ShadowRunRecord` directly.

Allowed fields:

- `contract_version`;
- `shadow_record_id`, `agent_run_id`, `run_id`;
- `event_type`, `status`;
- `created_at`, `completed_at`;
- `requires_reapproval`;
- safe fingerprints;
- safe lineage fields;
- non-negative timing summaries;
- sanitized warning/error codes, stages, and categories;
- safe gate/preflight summaries;
- safe persistence metadata such as evidence fingerprint, version, and commit.

Prohibited by default:

- complete question text;
- complete generated SQL;
- complete approved SQL;
- complete repaired SQL proposal;
- raw semantic context;
- n8n output payloads;
- result rows;
- raw provider responses;
- DSN, credentials, cookies, tokens, authorization headers, or secrets;
- stack traces or raw repository exceptions.

## List Contract

`GET /v1/internal/agent-runs/{agent_run_id}/shadow-runs` returns a deterministic
list ordered by `created_at`, `event_type`, and `shadow_record_id`.

The list uses an explicit `limit` query parameter:

- default: `50`;
- minimum: `1`;
- maximum: `100`;
- invalid values return `400`;
- decimal values with leading zeroes are accepted as decimal integers;
- repeated `limit` parameters return `400`;
- unknown query parameters are ignored.

The repository currently exposes `list_by_agent_run_id` without a native limit,
so this microstep applies the limit after repository read. Native bounded
repository reads are future debt before larger operational use.

## Visualization Contract

`GET /v1/internal/shadow-runs/{shadow_record_id}/visualization` returns neutral
JSON:

```json
{
  "contract_version": "1",
  "run": {},
  "steps": [],
  "edges": [],
  "flags": {}
}
```

The endpoint does not return Mermaid by default. Mermaid remains a CLI and
documentation artifact. A future UI should consume this neutral JSON model.

Step metadata is the safe allowlisted metadata generated by the visualization
mapper and is not serialized from arbitrary evidence dictionaries.

## HTTP Status

```text
200 success
400 invalid id, query, or forbidden browser identity headers
404 shadow record not found
405 invalid method
406 unacceptable Accept header
500 unexpected internal failure without details
503 repository unavailable or response too large
```

Errors use a safe shape:

```json
{"contract_version":"1","error":{"code":"SHADOW_REPOSITORY_UNAVAILABLE"}}
```

No raw exception message, DSN, SQL, traceback, cookie, token, authorization
header, or credential is returned.

## Internal Access

Service-to-service authentication is not implemented in this microstep.
Therefore this API is not production-ready and must stay behind controlled
internal TEST network access and allowlisting. Browser auth, cookies, hardcoded
API keys, and public internet exposure are explicitly out of scope.

Production exposure is blocked until explicit internal authentication,
authorization, network policy, and audit requirements are approved.

## Read-Only Guarantee

The read API only calls:

- `fetch_by_shadow_record_id`;
- `list_by_agent_run_id`;
- the neutral visualization mapper.

It does not call repository `create`, `update_evidence`, or `finalize`. It does
not execute SQL, repair SQL, generate SQL, call external providers, or mutate
shadow evidence.

## Future Debt

- Native repository-level limit/pagination for large shadow evidence stores.
- Optional Mermaid rendering endpoint only if explicitly approved.
- Internal service-to-service auth and audit trail before production exposure.
